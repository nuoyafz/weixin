按这个顺序来

第一次使用，从上到下完成。

  1. 链接/复制 _internal
  2. 运行 start.bat 建环境
  3. 配置模型接口与密钥
  4. 填写业务资料
  5. 打开并登录微信
  6. 点击一键检测
  7. 检测通过后启动
  8. 使用小号测试
01

第一次使用

先把运行环境和模型接口配好，再启动助手。

  1. 把原 VisionLeadAgent 的 _internal 目录链接或复制到本项目根目录（内含 RapidOCR 与 ONNX Runtime）。
  2. 运行 start.bat（或 python setup.py），自动创建虚拟环境并安装 PySide6、OpenCV、RapidOCR 等依赖。
  3. 打开 config.yaml，填好 vision_model 与 text_model 的接口地址、API Key 和模型名称（默认已接 Aliyun maas compatible-mode/v1）。
  4. 在“系统设置”里点“立即检查”做模型检测，显示可用后保存。
  5. 填好业务资料（知识库 / 回复风格等），先用自己的微信小号试几条消息。
模型与 OCR 都走本地 + 你自己的大模型接口，无需任何付费授权。
02

启动前看一遍

这些地方不对，最容易出现检测失败或不回复。

  • 当前支持 Windows 10 / 11（依赖 win32 与虚拟显示器驱动）。
  • 微信使用浅色模式和默认字体。
  • 只打开一个微信主窗口，并确认已经登录。
  • 微信停在正常聊天主界面，不要最小化。
  • 后台挂机依赖虚拟显示器（managed display），首次需安装虚拟显示驱动。
  • 确认 config.yaml 里的模型接口地址以 /compatible-mode/v1 结尾。
有一项不符合，先按软件提示改好，再点一次“一键检测”。
03

启动助手

打开微信，检测通过后再启动。

  1. 先打开并登录微信。
  2. 回到助手，点击“一键检测”，确认后台 / 虚拟屏状态正常。
  3. 检测通过后，点击“启动助手”。
  4. 右侧“微信真实画面”能看到微信，就可以开始使用；用小号发消息测试。
助手运行时可以正常用其他软件，但不要去动后台屏里的微信。需要自己回复客户时，先点“暂停助手”。命令行挂机用 python run.py --offscreen。
04

模型检测与速度检查

启动前先确认模型接口可用、回复够快。

系统设置

点“立即检查”做模型检测

会检测连通性、鉴权和模型是否存在，并连续跑几轮回复，给出平均 / 最快 / 最慢延迟与评级。检测不通过先看“模型日志”里的具体原因。

去启动助手
  • 检测报 404 / 模型不存在：检查 model 名称是否写错。
  • 检测报鉴权失败：检查 api_key 是否正确。
  • 延迟偏慢：换更小模型，或调低 max_tokens / timeout_seconds。
05

虚拟显示器不可用

后台挂机依赖虚拟显示器，先装好驱动再检测。

首次运行时看到 Windows 安全提示

名称显示为“MikeTheTech 显示适配器”、发布者显示为“SignPath Foundation”时，请点击“安装”。这是虚拟显示器驱动的确认窗口，后台挂机需要它。

已经装过驱动的电脑，重新运行时可能不会再次出现这个窗口，这是正常的。

驱动装好后，助手会把微信放到屏外虚拟屏，全程不闪现桌面。
先试这个

重新做一次检测

驱动装好一般不用重启。

  1. 确认虚拟显示驱动已安装。
  2. 回到助手，重新点击“一键检测”。
还是检测不到

重启后再检查

按下面的顺序做一遍。

  1. 先重启一次电脑。
  2. 打开“设置 → 系统 → 显示”，确认能看到虚拟显示器。
  3. 重新打开助手。
  4. 回到助手，重新点击“一键检测”。
一键检测通过，就可以启动助手。
重启后仍检测不到虚拟显示器，请把运行日志发来排查。
远程控制时看不到主屏怎么办？

在远程控制软件里找“切换显示器”或“查看所有屏幕”。需要动微信时先暂停助手；只调整微信窗口或输入框，调完直接继续，不用重新检测。

06

软件不回复，按这个顺序查

先检测，再看微信输入框和模型。

先点一次“一键检测”。没有通过就按提示处理；检测通过还是不回复，再看微信输入框。

检测通过还是不回：多数情况是输入框太矮。先暂停助手，把微信窗口调成接近方形，再把输入框上边缘往上拖，让输入区明显高一些。

不合适

输入框太矮

输入区太矮时，容易找不准输入框和发送按钮的位置，导致点不到或发不出。

这样就可以

把输入框拉高

把微信中间那条横线往上拖，让输入框明显高一些，助手定位更稳。

  1. 打开并登录微信，回到助手点击“一键检测”。
  2. 检测没通过，按提示处理（多为模型接口或虚拟屏问题）后再检测。
  3. 检测通过还是不回，暂停助手，把微信窗口调成接近方形，再拉高输入框。
  4. 确认微信是浅色模式，停在正常聊天页面。调完直接启动或继续助手，不用再次检测。
  5. 用小号发消息测试。还是不回复，再检查模型并看“模型日志”。
状态显示“本轮未回复”是什么意思？

这条消息被系统跳过了。常见情况是系统通知、自己刚发的消息、黑名单联系人，或者这条内容需要人工确认。点“模型日志”可以看具体原因。

一会能回复，一会不能回复怎么办？

先做一次“一键检测”。检测通过后，再看输入框是不是太矮、微信窗口是不是太扁。只调整微信窗口或输入框，调完直接启动或继续助手，不用重新检测。

多条消息没有完整回答怎么办？

用小号把完整问题再发一次。还是漏答，就把测试时间、消息内容和运行日志一起发来排查。

07

需要帮助

把时间、消息内容、配置和日志一起发来，定位会快很多。

反馈时带上这些

  • 问题发生的大概时间。
  • 客户发送的消息内容。
  • 软件当时显示的状态或提示（可看“模型日志”）。
  • 运行日志 logs/ 目录，以及 config.yaml 关键配置（注意脱敏 API Key）。
别只发一句“软件不回复”。带上时间、消息内容、配置和日志，才能更快查到原因。

提交反馈

把运行日志、脱敏后的 config.yaml 和复现步骤一并发到项目仓库或开发者。出现异常时，先暂停助手，再收集信息。
